# Locale

This monorepo uses [Paraglide JS](https://inlang.com/m/gerre34r/library-inlang-paraglideJs) for client-side UI translations. Message copy lives in a shared inlang project; each frontend app compiles its own Paraglide runtime from that source.

There is **no** shared `@beep/locales` runtime package. Do not add parallel TS dictionaries or compatibility layers.

## Architecture

```
project.inlang/                 ← shared source of truth (Git)
├── settings.json               ← locales, plugins, file patterns
└── messages/
    ├── en.json
    └── zh.json
        │
        ├── apps/web            → paraglide compile → src/locale/paraglide/  (generated, gitignored)
        ├── apps/admin          → (future) same pattern
        └── apps/mobile         → (future) same pattern
```

| Layer              | Location                                      | Role                                      |
| ------------------ | --------------------------------------------- | ----------------------------------------- |
| Message source     | `project.inlang/messages/*.json`              | All UI copy; edit here only               |
| Project config     | `project.inlang/settings.json`                | Locales list, inlang plugins              |
| Key tooling        | `scripts/check-locale-keys.ts`, `scripts/sort-locale-keys.ts` | CI/dev parity and sorting     |
| App runtime (web)  | `apps/web/src/locale/paraglide/`              | Generated by Paraglide; do not edit       |
| App helpers (web)  | `apps/web/src/lib/locale.ts`                  | Re-exports `m`, `getLocale`, `locales`, … |
| Server middleware  | `apps/web/src/locale/middleware.ts`           | Wraps `paraglideMiddleware` for SSR       |
| Locale switcher    | `apps/web/src/components/layout/locale-switcher.tsx` | UI to change locale              |

Non-Paraglide consumers (for example Rails `core/`) may read `project.inlang/messages/*.json` directly or maintain their own format; the JSON files in `project.inlang/` remain the canonical UI message source for the monorepo.

## Locales

- Base locale: `en`
- Additional locale: `zh`
- Default English URLs are unprefixed: `/$account_slug/beeps`
- Chinese URLs use a prefix: `/zh/$account_slug/beeps`

Paraglide strategy for `apps/web`: `url`, `cookie`, `baseLocale` (see `apps/web/vite.config.ts`).

## Message keys

Keys in `project.inlang/messages/*.json` use **snake_case** with a namespace prefix:

```json
{
  "common_save": "Save",
  "beeps_run_success": "Success",
  "marketing_hero_title": "Beep when it matters"
}
```

Paraglide generates a typed function per key. JSON key `common_save` → `m.common_save()`.

Use `{param}` placeholders for interpolation:

```json
{
  "account_pick_account_last_used": "Last used: {slug} — pick an account to continue."
}
```

```ts
m.account_pick_account_last_used({ slug: "acme" });
```

Some values are JSON-encoded strings (for example lists). Use helpers in `apps/web/src/lib/locale.ts`:

```ts
import { getMessageList } from "@/lib/locale";

const steps = getMessageList(m.push_help_steps());
```

## Message access in `apps/web`

Prefer importing from the Paraglide messages module:

```ts
import { m } from "@/locale/paraglide/messages";

m.common_save();
```

For locale utilities together with messages, use the app helper barrel:

```ts
import { getLocale, locales, m } from "@/lib/locale";
```

Runtime locale detection and URL localization come from `@/locale/paraglide/runtime` (re-exported by `@/lib/locale`):

```ts
import { getLocale, localizeHref, deLocalizeHref, setLocale } from "@/locale/paraglide/runtime";
```

## Commands

From the repo root:

```bash
pnpm locale:sort      # sort message keys alphabetically in en.json and zh.json
pnpm locale:check     # verify en/zh key parity and non-empty values
pnpm locale:compile   # compile Paraglide runtime for apps/web
```

Equivalent `mise` tasks: `mise run locale:sort`, `mise run locale:check`, `mise run locale:compile`.

`mise run dev` / `mise run web:dev` and `mise run web:build` compile Paraglide automatically via the Vite plugin in `apps/web/vite.config.ts`. Manual compile is only needed for one-off checks or tooling that reads generated files outside Vite.

## Adding copy

1. Add the key to **both** `project.inlang/messages/en.json` and `project.inlang/messages/zh.json`.
2. Run `pnpm locale:sort`.
3. Run `pnpm locale:check`.
4. Restart the dev server, or run `pnpm locale:compile`.
5. Call `m.your_new_key()` in the app.

## Adding i18n to a new frontend app

Each app owns its Paraglide output directory. Point every app at the same inlang project:

1. Add `@inlang/paraglide-js` to the app.
2. Configure the Vite plugin (or a `locale:compile` script):

   ```ts
   paraglideVitePlugin({
     project: "../../project.inlang",
     outdir: "./src/locale/paraglide",
     strategy: ["url", "cookie", "baseLocale"], // adjust per platform
     emitTsDeclarations: true,
   });
   ```

   Or CLI:

   ```bash
   paraglide-js compile \
     --project ../../project.inlang \
     --outdir ./src/locale/paraglide \
     --strategy url cookie baseLocale \
     --emit-ts-declarations
   ```

3. Gitignore `src/locale/paraglide/`.
4. Import messages with `import { m } from "@/locale/paraglide/messages"`.

Do **not** share a compiled Paraglide bundle across apps in `packages/` — locale strategy, routing, and SSR differ per app. Share only `project.inlang/`.

If a shared UI package needs translated strings, pass rendered strings or message functions from the app layer rather than compiling Paraglide inside the package.

## What not to do

- Do not recreate `@beep/locales` or any runtime dictionary package for Paraglide apps.
- Do not duplicate message JSON outside `project.inlang/messages/`.
- Do not hand-edit `apps/web/src/locale/paraglide/` — it is generated output.
- Do not edit `project.inlang/cache/` — plugin cache only.
